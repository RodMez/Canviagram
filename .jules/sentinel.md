## 2024-10-08 - [Timing Attack in Secret Comparison]
**Vulnerability:** The API endpoint `app/api/reminders/run/route.ts` compared the provided `x-reminder-sweep-secret` header against the expected secret (`env.REMINDER_SWEEP_SECRET`) using a simple string equality check (`!==`).
**Learning:** Simple string equality comparison (`===` or `!==`) returns early upon finding the first mismatched character. This allows attackers to deduce the secret character by character by measuring the response time, which is known as a timing attack.
**Prevention:** Use a timing-safe equality comparison function, such as `timingSafeEqual` from the `crypto` module (Node.js standard library), which compares strings in constant time. Make sure to check the lengths first before passing the buffers to `timingSafeEqual`, as it throws an error if lengths do not match.

## 2024-10-09 - [Timing Attack Mitigation Bypass due to Invalid Dummy Hash]
**Vulnerability:** The dummy hash used in `app/api/auth/login/route.ts` to mitigate timing attacks (`$2a$10$dummyhashdummyhashdummyhashdummyha`) was mathematically invalid. This caused the `bcrypt.compare` function to fail instantly when evaluating incorrect users, re-introducing the timing vulnerability it was supposed to prevent.
**Learning:** Security functions like `bcrypt.compare` expect data in a specific format and length. If a mitigation strategy relies on executing these functions with fake data to normalize response times, the fake data must be formatted correctly so the function actually performs the computationally expensive operations, rather than throwing an early validation error.
**Prevention:** Always use a mathematically valid string (such as an actual valid bcrypt hash) for dummy parameters intended to equalize execution times. Validate that timing attacks are actually mitigated by comparing the execution time of the happy path and the mitigated error path.
