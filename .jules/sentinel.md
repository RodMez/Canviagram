## 2024-05-15 - Timing Attack Prevention in Secret Comparison
**Vulnerability:** A timing attack vector existed in the `POST /api/reminders/run` endpoint where an API secret string (`env.REMINDER_SWEEP_SECRET`) was being compared against an incoming header (`x-reminder-sweep-secret`) using standard string equality `!==`.
**Learning:** Standard string equality (`===` or `!==`) operators short-circuit the comparison upon finding the first mismatched character. This makes the time it takes for the comparison to complete dependent on how many leading characters are correct. An attacker can theoretically exploit these subtle timing variations to deduce a secret, character by character.
**Prevention:** In security-sensitive scenarios, especially API keys or secrets passed from external contexts, always use constant-time comparison algorithms. In Node.js environments, this means using `crypto.timingSafeEqual()`, which takes the same amount of time regardless of where the mismatch occurs. Additionally, check buffer lengths first, as passing unequal buffers to `timingSafeEqual()` will throw an error.
